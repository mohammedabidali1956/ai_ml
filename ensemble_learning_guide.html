Ensemble learning — interactive guide covering bagging, boosting, random forests, and voting classifiers

The core idea — wisdom of the crowd

A single model is like asking one person for an answer. That person might be wrong. But if you ask 100 people and take the majority answer — you're much more likely to be right.

That is ensemble learning in one sentence: combine many models to get a better answer than any single model could give you.

Real example: A doctor diagnosing a rare disease. One doctor might miss it. But a panel of 5 specialists, each checking independently, is far less likely to all miss the same thing at the same time.

Why does combining models improve performance?

Reduces variance
One tree might overfit. 100 trees averaged out — the overfitting cancels.
Reduces bias
Boosting corrects errors one by one. Each model fixes what the last one got wrong.
Improves robustness
No single bad model can dominate. The group corrects outlier predictions.

Bagging (Bootstrap Aggregating)

Each model trains on a different random sample of data (sampled WITH replacement). Then all models predict, and we take a vote (classification) or average (regression).

Reduces VARIANCE. Each model sees different data so they overfit differently. Their mistakes cancel out when averaged.

Key word — "with replacement": the same row can appear multiple times in one sample. This is called bootstrapping.

Boosting — models learn from each other's mistakes

Models are trained ONE AFTER ANOTHER. Each new model pays extra attention to the rows that the previous model got wrong.

Model 1
misses rows 3,7,12
→
Model 2
focuses on 3,7,12

Model 3
fixes remaining errors
→
Final answer
weighted combo
Reduces BOTH bias and variance. Specifically targets hard-to-predict cases.
Slower than bagging — models can't train in parallel because each depends on the previous one.

Examples from your notes: AdaBoost, Gradient Boosting, XGBoost, LightGBM. XGBoost is the most popular one in industry and competitions.

Stacking — meta-model combines base models

Train multiple different model types (LogisticRegression, DecisionTree, k-NN). Then train a SECOND model (called a meta-model) that learns: "given what these 3 models predicted, what is the best final answer?"

Level 0 — base models all see the data and predict:
LogReg → 0.72
DecTree → 0.68
k-NN → 0.75
Level 1 — meta-model sees [0.72, 0.68, 0.75] as inputs and predicts final answer:
Meta-model → 0.79 (better than any base model!)
The meta-model learns to trust some base models more than others in different situations. Very powerful but complex to implement correctly.

Random forest = bagging + feature randomness

A decision tree is a good model but overfits easily — it memorises the training data. Random Forest fixes this by:

Bootstrap sampling
Each tree trains on a different random subset of rows (with replacement).
Feature randomness
Each split only considers a random subset of features (not all features). This makes trees less correlated with each other.
Prediction aggregation
Classification: majority vote. Regression: average of all trees.
Feature randomness is what makes Random Forest special compared to plain bagging. If one feature is very dominant, every tree in plain bagging would use it first — they'd all be correlated and similar. By restricting features per split, trees become diverse, and diverse trees make better ensembles.

from sklearn.datasets import load_iris from sklearn.model_selection import train_test_split from sklearn.preprocessing import StandardScaler from sklearn.linear_model import LogisticRegression from sklearn.tree import DecisionTreeClassifier from sklearn.neighbors import KNeighborsClassifier from sklearn.ensemble import VotingClassifier from sklearn.metrics import accuracy_score
StandardScaler is imported here because k-NN and Logistic Regression are sensitive to feature scale. DecisionTree is NOT scale-sensitive but scaling it doesn't hurt.
X_train = scaler.fit_transform(X_train) X_test = scaler.transform(X_test) # fit_transform on train: learn mean & std from training data, apply it # transform on test: apply SAME mean & std — do NOT fit again on test data
This is the most common mistake beginners make. If you call fit_transform on test data, the scaler learns different statistics — the test set is no longer comparable to train. Always: fit on train, transform both.
log_model.fit(X_train, y_train) dt_model.fit(X_train, y_train) knn_model.fit(X_train, y_train) # Each model trains independently on the same training data
ensemble_model = VotingClassifier( estimators=[ ('log_reg', log_model), ('decision_tree', dt_model), ('knn', knn_model) ], voting='hard' # ← 'hard' means majority vote on predicted CLASS LABELS # ← 'soft' would average predicted PROBABILITIES (often better) )
voting='hard' — each model votes for a class (e.g. 0 or 1 or 2), majority wins. voting='soft' — each model outputs probabilities (e.g. [0.2, 0.7, 0.1]), these are averaged, highest average wins. Soft voting is usually more accurate when models output well-calibrated probabilities.
ensemble_model.fit(X_train, y_train) # Note: VotingClassifier re-trains all base models internally. # So you don't actually need to train them separately above. # The individual training above was just done to get individual accuracy scores.

rf_model = RandomForestClassifier(random_state=42) rf_model.fit(X_train, y_train) y_pred = rf_model.predict(X_test)
random_state=42 makes results reproducible. Without it, random forest picks different random subsets each run and gives slightly different results every time.

There is a bug in the original code: 'None' (with quotes) is a string, not Python's None value. sklearn's max_features does not accept the string 'None'. Remove the quotes: use None directly.
