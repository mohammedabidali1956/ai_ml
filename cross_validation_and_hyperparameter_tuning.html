Cross-validation and hyperparameter tuning — interactive learning guide

The problem cross-validation solves

Imagine you scored 90% on one exam. Is that reliable? What if it was a lucky paper? What if you practised EXACTLY those questions?

Same problem in ML. If you train on 80% of data and test on the remaining 20%, your result depends heavily on WHICH 20% you picked. One lucky split can make a bad model look great.

Cross-validation says: "don't test on just one split — test on ALL possible splits and average the results." That gives you a much more trustworthy score.

Stratified K-Fold — for imbalanced data

Regular K-Fold just randomly splits rows. Problem: what if your dataset has 90% class A and 10% class B? By pure bad luck, one fold might end up with NO class B samples at all.

Stratified = "proportional". Each fold mirrors the class distribution of the full dataset. Use this for classification problems always.

LOOCV — Leave-One-Out Cross-Validation

Extreme version of K-Fold where K = number of data points. Each time, ONE data point is the test set and all others are training.

Use when?
Small datasets only
If you have 10,000 rows, LOOCV trains the model 10,000 times. Use K-Fold (K=5 or 10) instead for large datasets.

Parameters vs hyperparameters — the key difference

These two words sound similar but mean very different things:

Parameters (learned automatically)
The model learns these from data during training. You never set them manually.
Examples: weights in a neural network, coefficients in linear regression
Hyperparameters (you set before training)
These control HOW the model learns. You must choose them yourself.
Examples: max_depth, learning_rate, n_estimators, C, kernel
Analogy: training a student for an exam. The student's memory of facts = parameters (learned from studying). How many hours per day to study, which topics to focus on = hyperparameters (you decide before studying begins).

Grid Search — tries every combination

You define a grid of values to try. Grid Search tests every single combination and picks the best one.

param_grid = { 'max_depth': [3, 5, 10], 'learning_rate': [0.01, 0.1, 0.5] } # Total combinations: 3 × 3 = 9 runs

Click "Run Grid Search" to see it work through all combinations:

Grid Search is thorough but slow. If you have 5 hyperparameters each with 5 values = 5⁵ = 3125 runs. Each run trains a full model. With cross-validation it multiplies: 3125 × 5 folds = 15,625 model trainings!

Random Search — smarter for large spaces

Instead of trying every combination, Random Search samples a fixed number of random combinations from the space.

from sklearn.model_selection import RandomizedSearchCV param_dist = { 'max_depth': [3, 5, 7, 10, 15, 20], 'learning_rate': [0.001, 0.01, 0.05, 0.1, 0.3, 0.5] } # 6×6 = 36 possible combinations # Random Search tests only 10 (n_iter=10) rs = RandomizedSearchCV(model, param_dist, n_iter=10, cv=5)
Research shows that random search finds good hyperparameters nearly as well as grid search — but much faster. The reason: usually only 1-2 hyperparameters really matter. Random sampling covers more of the important ones.
Grid Search
Tests ALL combinations. Guaranteed to find the best in your grid. Slow for large spaces.
Random Search
Tests N random combinations. Faster. Near-optimal for large hyperparameter spaces.

Underfitting — model is too simple

The model hasn't learned enough from the data. It performs badly on both training data AND new data.

Like a student who barely studied. Gets bad marks in both practice tests and the real exam.
Signs of underfitting: - Training accuracy: LOW - Validation accuracy: LOW - Both scores are similarly bad Fix: use a more complex model, add more features, increase max_depth, train for longer

Overfitting — model is too complex

The model memorised the training data including its noise. Performs great on training data but badly on new data.

Like a student who memorised the exact practice questions but can't handle any variation in the real exam.
Signs of overfitting: - Training accuracy: HIGH (e.g. 99%) - Validation accuracy: LOW (e.g. 65%) - Big gap between the two scores Fix: reduce max_depth, add regularisation, get more training data, use cross-validation

How cross-validation detects overfitting

This is the whole point. Without cross-validation you might only check training accuracy and think your model is great. Cross-validation forces the model to prove itself on data it has never seen — every time.

from sklearn.model_selection import cross_val_score scores = cross_val_score(model, X, y, cv=5, scoring='accuracy') print(scores) # [0.88, 0.91, 0.87, 0.90, 0.89] ← each fold's score print(scores.mean()) # 0.89 ← reliable average print(scores.std()) # 0.014 ← low std = consistent, not overfitting # If you see training accuracy 0.99 but CV score 0.65 → OVERFITTING
Low cross-validation std (standard deviation) = model is consistent across different data slices = trustworthy model. High std = model is sensitive to which data it sees = might be overfitting.

Task 3 — Grid Search for hyperparameter tuning

from sklearn.model_selection import GridSearchCV model = RandomForestClassifier(random_state=42) param_grid = { 'n_estimators': [50, 100, 200], # number of trees 'max_depth': [3, 5, 10, None], # depth of each tree 'min_samples_split': [2, 5, 10] # min samples to split a node } # Total: 3 × 4 × 3 = 36 combinations × 5 folds = 180 model trainings grid_search = GridSearchCV( estimator=model, param_grid=param_grid, cv=5, scoring='f1', n_jobs=-1, # use all CPU cores verbose=1 ) grid_search.fit(X, y) print("Best params:", grid_search.best_params_) print("Best F1: ", grid_search.best_score_.round(3)) # Use the best model for predictions best_model = grid_search.best_estimator_
n_jobs=-1 tells sklearn to use all your CPU cores in parallel. Without it, 180 trainings happens one by one. With it, it runs many simultaneously — much faster.
